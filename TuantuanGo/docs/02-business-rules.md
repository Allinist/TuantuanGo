# 业务规则说明

## 1. 商品基础信息

首期分类为“出谷子/文创”。

每个商品至少包含：

- 商品名称。
- 定价。
- 图片。
- 简介描述。
- 库存数量。
- 状态：上架、下架、售罄。
- 所属团。
- 所属销售规则。
- 同款商品编号标记，可为空。

团长/卖家应支持一次增加 N 款商品。批量上架时，每一行商品都应拥有独立库存，发布前再按上架模式生成销售组合。

### 1.1 同款多数量商品编号

当同一商品有多个实物库存，且每个实物存在图案、瑕疵、编号、拍照位置或买家偏好差异时，团长/卖家可以为同款商品配置编号标记。

规则：

- 编号标记属于商品库存的细分项，不改变商品名称和基础价格。
- 编号标记应在买家选择商品、购物车、订单明细和发货拣货页面展示。
- 若买家按编号选择，则下单时应锁定对应编号，避免同一编号被重复售出。
- 若买家只选择数量不指定编号，系统可由团长发货前分配编号，分配后应记录到订单明细。
- 编号标记可包含短文本，如 A1、B2、左上、瑕疵 03；不建议承载长描述，长描述应放在商品说明中。

## 2. 销售规则

### 2.1 批量上架与模式选择

团长/卖家批量新增商品后，需要为每个商品选择上架模式。模式决定商品能否单独出售、是否参与组合、如何计算组合库存。

上架模式：

- 打包直出：多个商品组成固定销售包，买家按包购买。
- 捆：商品作为捆出主商品，买家购买时必须搭配被捆商品。
- 被捆：商品只作为被捆商品出现，不能独立作为主商品购买。
- 直接团购：商品直接参与单人团或多人拼团购买。
- 普通直出：商品可单独购买。
- 普通自选：商品进入自选池，买家可自由选择。

销售组合生成规则：

1. 批量录入 N 款商品及各自库存。
2. 为每款商品选择上架模式。
3. 系统根据模式生成销售组合草稿。
4. 团长补充组合价、组合库存、限购、邮费和规则说明。
5. 发布前校验组合内商品库存是否满足组合库存。
6. 发布后买家只能看到已发布销售组合和可购买商品。

组合库存规则：

```text
组合库存 <= min(组合内每个商品的 floor(商品可售库存 / 组合内需要数量))
```

若组合内商品同时参与多个组合，下单时仍必须回到商品级库存做事务校验，避免不同组合之间超卖。

### 2.2 打包直出

打包直出表示多个商品作为一个固定包出售。

配置项：

- 包名称。
- 包内商品和每个商品需要数量。
- 包价，可等于或低于包内商品原价之和。
- 包库存。
- 是否允许同一买家购买多个包。

买家流程：

1. 进入打包直出组合。
2. 查看包内商品清单和包库存。
3. 选择购买包数量。
4. 加入购物车或提交订单。

价格计算：

```text
商品总价 = 包价 * 包数量
订单总价 = 商品总价 + 邮费 + 其他费用
```

库存校验：

```text
每个包内商品可售库存 >= 包内需要数量 * 包数量
```

### 2.3 直出

直出表示商品可以直接购买，不要求搭配其他商品。

配置项：

- 是否包邮。
- 若不包邮，填写邮费。
- 可购买数量上限。
- 库存数量。

买家流程：

1. 进入直出商品列表。
2. 选择商品和数量。
3. 加入购物车。
4. 提交订单。

价格计算：

```text
商品总价 = 商品单价 * 数量
订单总价 = 商品总价 + 邮费
```

若包邮，则邮费为 0。

### 2.4 捆出

捆出表示买家购买主商品时，必须同时购买被捆商品。

捆出第一页：

- 展示主商品。
- 展示捆绑规则。
- 展示被捆商品摘要。

#### 2.4.1 指定捆金额模式

团长设置一个最低被捆金额，例如“需捆 50 元”。

买家第二页：

- 展示可选被捆商品列表。
- 买家自由选择被捆商品。
- 已选被捆商品总额必须大于等于指定捆金额。
- 允许超出指定捆金额。

校验规则：

```text
被捆商品金额 >= 指定捆金额
```

订单金额：

```text
订单总价 = 主商品金额 + 被捆商品金额 + 邮费 + 其他费用
```

#### 2.4.2 固定捆物品模式

团长预先指定固定被捆商品组合。

买家第二页：

- 直接展示固定捆物表单。
- 买家只能确认固定组合，不能替换被捆商品。

校验规则：

```text
主商品库存充足
固定被捆商品库存均充足
```

订单金额：

```text
订单总价 = 主商品金额 + 固定被捆商品金额 + 邮费 + 其他费用
```

### 2.5 被捆商品

被捆商品是捆出规则中的搭配商品。

规则：

- 被捆商品可以只作为被捆出现，也可以同时允许普通自选或直出，但必须由团长明确配置。
- 仅作为被捆的商品，不展示独立购买按钮。
- 被捆商品库存参与捆出组合库存校验。
- 被捆商品可设置被捆价；若未设置，则使用商品原价。

### 2.6 直接团购

直接团购表示商品直接参与团购，不依赖捆绑或自选池。

配置项：

- 团购价。
- 团购库存。
- 单人团或多人拼团。
- 起团/发车条件。
- 限购数量。

买家流程：

1. 进入直接团购商品。
2. 查看团购价、库存和发车条件。
3. 选择数量。
4. 加入购物车或提交订单。

直接团购可以复用单人团和多人拼团状态机。多人拼团商品必须展示发车进度。

### 2.7 自选模式

自选模式没有捆绑关系，商品选择页面直接显示所有可选商品。

团长可配置：

- 满多少包邮。
- 固定邮费。
- 打包费。
- 物料费。
- 小费。
- 其他自定义费用项。

买家流程：

1. 进入商品选择页。
2. 选择任意商品和数量。
3. 加入购物车。
4. 提交订单。

价格计算：

```text
商品总价 = 所有商品单价 * 数量之和
基础费用 = 打包费 + 物料费 + 小费 + 其他费用
若商品总价 >= 包邮门槛，则邮费 = 0
否则邮费 = 固定邮费
订单总价 = 商品总价 + 邮费 + 基础费用
```

## 3. 团类型

### 3.1 单人团

单人团更接近抢购。

特点：

- 买家下单后按库存直接确认占用。
- 不需要等待其他买家满足发车条件。
- 适用于现货、少量库存、先到先得。

### 3.2 多人拼团

多人拼团需要团长设置发车条件。

发车条件可以包含：

- 指定商品必须被下单并确认。
- 指定商品组合必须达到一定数量。
- 总订单金额达到指定门槛。
- 总确认人数达到指定人数。

首期建议优先实现“部分商品必须已被下单并确认”。

示例：

```text
发车条件：A 商品、B 商品必须均至少有 1 件被下单并由团长确认。
```

状态变化：

```text
进行中 -> 发车条件满足 -> 已发车
```

是否自动发车可由团长配置，首期建议默认手动确认发车。

## 4. 购物车与库存

### 4.1 购物车

购物车按团维度隔离。一个购物车只对应一个团，避免跨团计算邮费和规则。

购物车项应记录：

- 商品。
- 数量。
- 销售规则类型。
- 若为捆出，记录主商品和被捆商品关系。
- 创建时间和更新时间。

### 4.2 库存扣减策略

用户从购物车下单时，系统使用贪心算法扣除库存，并提醒库存不足的商品。

建议实现方式：

1. 将购物车商品按规则优先级排序。
2. 优先扣减强约束商品，如打包直出包内商品、捆出主商品、固定捆商品、发车条件商品。
3. 再扣减普通商品。
4. 若某个商品库存不足，记录不足项并返回给买家。
5. 所有需要扣减的商品都满足库存时，创建订单并进行库存预占或实际扣减。

推荐首期采用“下单即预占库存，团长审核失败后释放库存”的方式。

库存状态：

- available_stock：可售库存。
- reserved_stock：已下单待审核库存。
- sold_stock：已确认售出库存。

销售组合不替代商品库存。打包直出、捆出、直接团购等组合可以拥有展示库存，但最终下单必须扣减组合内实际商品库存。

下单时：

```text
available_stock -= order_quantity
reserved_stock += order_quantity
```

团长确认支付后：

```text
reserved_stock -= order_quantity
sold_stock += order_quantity
```

团长驳回或订单超时：

```text
reserved_stock -= order_quantity
available_stock += order_quantity
```

## 5. 订单状态

建议订单状态：

- pending_payment：待支付截图。
- pending_review：待团长审核。
- confirmed：团长已确认。
- rejected：团长已驳回。
- shipped：已发货。
- completed：已完成。
- transferred：已转单。
- cancelled：已取消，仅限未确认前。

核心限制：

- confirmed 之后，买家不允许取消订单。
- confirmed 之后，买家不允许删除已购商品。
- confirmed 之后，买家可以追加商品。
- confirmed 之后，买家可以申请合并发货。
- confirmed 之后，买家可以申请转单给其他人。
- shipped 之后，团长应填写物流单号或标记无需物流。
- completed 之后或达到评价开放条件后，买家可以评价团长。

## 6. 支付截图审核

首期流程：

1. 团长开团时上传收款二维码。
2. 买家确认订单页展示该二维码。
3. 买家完成外部支付后上传支付截图。
4. 系统保存截图并将订单置为 pending_review。
5. 团长人工审核截图。
6. 审核通过后订单置为 confirmed。
7. 审核失败后订单置为 rejected，并释放库存。

后续可扩展：

- OCR 识别付款金额。
- 微信支付接口。
- 平台担保交易。
- 自动到账核验。

## 7. 合并发货

买家可以对同一团长或同一团下的多个 confirmed 订单申请合并发货。

首期建议限制：

- 仅同一团长订单可合并。
- 已发货订单不可合并。
- 合并后生成合并发货记录。
- 合并发货记录应拥有独立物流单号。
- 被合并订单应展示同一合并发货单和物流轨迹。
- 若部分订单不适合合并，团长可以驳回并填写原因。

合并发货流程：

1. 买家选择可合并的订单并提交申请。
2. 系统校验订单归属、团长、发货状态和订单状态。
3. 团长审核申请。
4. 审核通过后生成合并发货记录。
5. 团长填写物流公司和物流单号。
6. 关联订单同步进入 shipped 或保持各自状态但展示合并物流。

## 8. 转单

转单表示买家将已确认订单转给其他买家。

首期建议只记录转单信息，不内置二次支付。

转单流程：

1. 原买家发起转单申请。
2. 填写接收人信息或选择平台用户。
3. 接收人确认。
4. 团长可查看转单记录。
5. 订单归属变更或生成转单关联记录。

建议保留完整历史，不覆盖原始买家信息。

限制：

- 已发货订单默认不可转单，除非团长手动允许。
- 接收人若在该团长黑名单中，不允许接收转单。
- 转单不改变原始支付截图和审核记录。
- 转单完成后，后续物流、收货和评价归属应按平台规则固定，建议由最终订单持有人处理。

## 9. 物流单号与物流追踪

团长发货时应填写物流公司和物流单号；同城自提、面交或无需物流场景可选择“无需物流”并填写说明。

物流规则：

- 普通订单可直接绑定一个物流单号。
- 合并发货订单绑定合并发货单号，多个订单共享一条物流轨迹。
- 物流轨迹可通过第三方物流查询接口同步，也可先由团长手动填写发货和签收状态。
- 买家可在订单详情复制物流单号并查看轨迹。
- 订单签收或买家确认收货后，可进入 completed。

## 10. 团长评分与评价

评价资格：

- 买家必须购买过该团长的商品。
- 评价必须关联真实订单。
- 订单状态至少为 confirmed，建议优先在 shipped 或 completed 后开放评价。
- 同一订单只能产生一条有效评价。

评价内容：

- 评分建议为 1 到 5 星。
- 可填写文字评价和上传图片。
- 可选择公开或匿名展示。
- 团长可回复评价，回复也需要审核。

违禁内容审核：

- 评价文本、图片和团长回复必须进入内容审核流程。
- 审核状态包括 pending、approved、rejected。
- rejected 内容不公开展示，并应保留审核原因。
- 平台管理员可复核误判内容。

## 11. 黑名单

黑名单用于限制高风险交易对象。

建议规则：

- 团长可将用户加入自己的黑名单。
- 黑名单用户不能在该团长的团中下单、接收转单或发布评价。
- 黑名单应记录原因、备注、操作人和生效时间。
- 买家侧不应看到过度暴露的黑名单原因，只提示无法参与该团。
- 后续可将高级黑名单能力设计为付费功能，如更高名额、批量导入、跨团同步和风险标签。
